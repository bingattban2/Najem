# نجم واي فاي — تسليم تحسين الإقلاع والواجهات وخطة اعتماد النواقص

## النطاق المعتمد
هذه النسخة تلتزم **بالتبسيط اللاحق المعتمد من المالك**: ثلاث شاشات رئيسية (الرئيسية، الإدارة، الإعدادات)، وسجل العمليات داخل الإدارة. إضافة الكروت ومحاسبة المتبقي هما العمليتان الظاهرتان. لا نعيد واجهة الأرشيف المنفصل أو تحصيل الديون أو المرتجعات أو مخزون المركز دون توجيه جديد؛ نحتفظ بالتاريخ والطبقات المتوافقة مع النسخ السابقة.

## المرحلة 1 — أُنجزت برمجيًا في هذه الحزمة
- إقلاع عادي مباشر إذا **لم** يوجد طلب ترحيل قاعدة بيانات مسجّل؛ الإقلاع الذي يحتوي طلب ترحيل يظل محجوبًا حتى استكمال التحقق أو استرجاع القاعدة الأصلية. لا تُفتح Room قبل انتهاء بوابة الترحيل.
- الاستغناء عن اشتراك واستعلام لكل باقة لصالح تجميع SQL واحد على مستوى الباقات، وآخر على مستوى باقات العميل؛ نفس معادلة الإضافة والخصم وقيم الصفر عند عدم وجود حركات.
- بطاقات باقات الرئيسية أصغر فقط، مع الحفاظ على الحجم السابق للبطاقات في تفاصيل العميل والإدارة.
- توسيط عناوين «مبيعات شهر»، «فئات الكروت»، «العملاء» في الرئيسية؛ دون تعديل أرصدة المبيعات.
- معلومات قراءة فقط في الإعدادات: الاسم الرسمي من موارد Android، الإصدار من APK المثبت، «فكرة وبرمجة / سعيد بن قطبان».

## المرحلة 2 — تعزيز الفحوص قبل إصدار النسخة
- اختبار Android إضافي لمطابقة إجمالي الباقات والحركات، ولتغيير الرصيد بعد محاسبة حقيقية.
- إصدار Release الموقّع لا يبدأ التوقيع قبل نجاح اختبارات JVM وAndroid emulator؛ مفاتيح المالك لا تدخل خطوات PR أو اختبارات عامة.
- تجنّب حذف أي جدول أو كود تاريخي قد تعتمد عليه عملية الاستعادة أو عملاء بإصدارات سابقة. تنظيف استيرادات HomeViewModel التي لم تعد مستخدمة بعد دمج الاستعلامات.

## المرحلة 3 — بوابة قبول تعتمد على جهاز فعلي واتصال Google (لم تُعتمد بعد)
1. تشغيل `:app:assembleDebug` و`:app:testDebugUnitTest` في Code On The Go؛ إصلاح أي فشل على نفس النسخة.
2. قياس زمن الإقلاع من النقر إلى أول شاشة تفاعلية على هاتف المستخدم وتكراره بعد إغلاق التطبيق، وقياس دخول شاشة عميل مع 10 و50 و100 باقة؛ لا تُستنتج أرقام زمنية من فحص المصدر.
3. على قاعدة بيانات اختبارية: تسليم ← محاسبة ← تحقق من الرصيد وسجل العمليات ← PDF حفظ/مشاركة/طباعة؛ أعِد المحاولة بعد فشل واعمل ضغطتين سريعتين.
4. النسخ الاحتياطي المشفر واستعادة النسخة من ملف محلي ثم من Google Drive على جهاز ثان، باستخدام OAuth مشروع المالك والصلاحيات وبصمات توقيع التطبيق. لا تُختبر هذه المرحلة بالاتصال الصوري أو بحسابات تطوير خارجية.
5. حالات قطع التشغيل أثناء ترحيل SQLCipher، والتحقق من عدم ضياع القاعدة الأصلية، واختبار القفل عند عودة التطبيق من الخلفية.
6. تشغيل الاختبارات الكاملة في GitHub Android CI؛ لا يُوقّع APK الإصدار إلا بعد اجتياز الاختبارات بمفاتيح توقيع المالك في بيئة آمنة.

## أسباب عدم حذف أقسام غير ظاهرة
- ملف الترحيل الآمن وكود SQLCipher وكيانات Room القديمة تمثل توافقًا وبيانات تاريخية؛ حذفها تجميليًا قد يعرّض بيانات العملاء للفقدان.
- عمليات مخفية في واجهة النسخة المبسطة قد تُستخدم عند قراءة أو تصدير تاريخ تم حفظه بنسخة سابقة.

## أوامر الفحص على جهاز Android
```bash
bash ./gradlew -Pandroid.aapt2FromMavenOverride="$HOME/android-sdk/build-tools/36.0.0/aapt2" :app:testDebugUnitTest :app:assembleDebug
```
اختبارات المحاكي/الجهاز:
```bash
bash ./gradlew -Pandroid.aapt2FromMavenOverride="$HOME/android-sdk/build-tools/36.0.0/aapt2" :app:connectedDebugAndroidTest
```
**الحالة:** اجتاز منطق SQL المجمّع اختبار تكافؤ مستقل باستخدام SQLite على بيانات محاكية؛ لم يتم تنفيذ بناء أندرويد أو اختبارات Android instrumented في حاوية التسليم بسبب غياب SDK/توزيعة Gradle. لا يُعتبر فحص النص بديلًا للبناء أو قياس الأداء على الهاتف.
