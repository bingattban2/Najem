# اعتماد واجهات Stitch في تطبيق نجم واي فاي

المرجع البصري: الملف المرفق `stitch_.zip`، وأخصّ النماذج التالية:

- `_2` الرئيسية الفاتحة و`_8` نظيرها الليلي: ترويسة ضمن المحتوى، عدادات صغيرة وشريط الفئة الملون، قائمة عملاء مضغوطة.
- `_1` تفاصيل العميل و`_7` النظير الليلي: بطاقة فئة صغيرة، موقع العميل، وإجراءات مثبتة (إضافة، محاسبة، تصدير).
- `_4` الإدارة و`_10` النظير الليلي: أربع بطاقات مقسمة إلى صفين وملخص مرتبط بالبيانات الحقيقية.
- `_5` إدارة الباقات: بطاقات مرتبة مع إمكانية تعديل/تفعيل/حذف.
- `_6` الإعدادات و`_12` نظيرها الليلي: شريط اختيار مستدير بين الحماية والنسخ الاحتياطي.
- `_11` سجل العمليات: بطاقات حالات مميزة، بحث وتاريخ وتصدير PDF.
- `_13` و`_14` تصميم إجراءات المحاسبة، و`pdf_1` إلى `pdf_4` مظهر أزرار حفظ/مشاركة/طباعة.
- الملف `najim_wifi_design_system/DESIGN.md`: أساس الألوان والخطوط والمسافات.

تمت إعادة صياغة هذه الأشكال باستخدام Jetpack Compose، لا عبر WebView أو نسخ JavaScript.
لم تُنسخ البيانات والأرقام المعروضة في لقطات النماذج، ولا الحقول الزائدة عن فكرة المشروع المبسطة.

## حدود التعديل
- **اسم التطبيق المعروض عند التثبيت:** إداره مبيعات الشبكة (`@string/app_name`).
- اسم الحزمة كما هو: `com.najimwifi.app`.
- الشريط السفلي يبقى بثلاث وجهات: الرئيسية، الإدارة، الإعدادات.
- سجل العمليات داخل الإدارة، لا يعود تابًا منفصلًا.
- لا تعديل على Room أو المخزون أو المحاسبة أو تسجيل الدخول أو قواعد النسخ والاستعادة أو محرك PDF.
- لا تحويل لنموذج Stitch التجريبي إلى مصدر للبيانات؛ القيم من نماذج التطبيق الفعلية.

## التحقق
- تحقق بنيوي من XML والحزم والفروق ومن وجود ملفات المصادر الأصلية.
- فحص Kotlin مستقل دون Android SDK لا يعتبر بناء Android؛ لم ينفَّذ APK أو اختبار الواجهات الحقيقي في بيئة التسليم.
- تحقق على Code On The Go بـ `:app:assembleDebug`، ثم معاينة الوضعين النهاري والليلي والحقول ذات أسماء الباقات الطويلة.
